## 🧪 Тест-кейсы для проверки

### ✅ Базовые тесты

- [ ] **Вход в админку**
  - Открыть `/admin/`
  - Ввести правильный пароль
  - Должна появиться панель управления

- [ ] **Неверный пароль**
  - Ввести неправильный пароль
  - Должна появиться ошибка "Неверный пароль!"
  - В логе должна быть запись `[WARNING] Login failed`

- [ ] **Сохранение цен**
  - Изменить цену любого абонемента
  - Нажать "Сохранить изменения"
  - Должно появиться сообщение "Изменения успешно сохранены!"
  - В логе: `[INFO] Content saved successfully`

- [ ] **Сохранение расписания**
  - Добавить новый день
  - Сохранить
  - Проверить, что день появился в `data/content.json`

- [ ] **Смена пароля**
  - Ввести новый пароль (минимум 5 символов)
  - Сохранить
  - Должно появиться сообщение "Пароль успешно изменен!"
  - Выйти и войти с новым паролем

### ✅ Тесты безопасности

- [ ] **CSRF защита**
  - Попробовать отправить форму без токена
  - Должна быть ошибка "Ошибка безопасности (CSRF)"

- [ ] **XSS защита**
  - Ввести в поле названия: `<script>alert('XSS')</script>`
  - Сохранить
  - При выводе скрипт должен быть экранирован

- [ ] **Валидация телефона**
  - Ввести некорректный телефон: `123`
  - Сохранить
  - В логе должно быть предупреждение

### ✅ Тесты интеграции

- [ ] **Синхронизация с БД**
  - Изменить расписание
  - Сохранить
  - Должно появиться сообщение "Расписание синхронизировано с ботом!"
  - В логе: `[INFO] [Zumba Admin DB Sync] Sync completed`

- [ ] **Ошибка БД (если БД недоступна)**
  - Остановить БД: `docker-compose stop db`
  - Попробовать сохранить расписание
  - Должна быть ошибка синхронизации в логе
  - Данные должны сохраниться в JSON

## 📊 Мониторинг после деплоя

### Проверка логов

```bash
# Последние 50 строк лога
docker exec -it zumba_php tail -n 50 /var/log/admin.log

# В реальном времени
docker exec -it zumba_php tail -f /var/log/admin.log

# Поиск ошибок
docker exec -it zumba_php grep "ERROR" /var/log/admin.log
```

### Проверка сессий

```bash
# Проверить файлы сессий
docker exec -it zumba_php ls -la /tmp/sessions/

# Должны быть файлы вида sess_<session_id>
```

### Проверка прав

```bash
# Проверить права на директории
docker exec -it zumba_php ls -la /var/www/html/
docker exec -it zumba_php ls -la /tmp/sessions/
docker exec -it zumba_php ls -la /var/log/
```

## 🔧 Решение проблем

### Проблема: Админка не открывается (403/404/500)

**Решение:**
```bash
# Проверить логи nginx
docker-compose logs nginx

# Проверить логи PHP
docker-compose logs php

# Проверить права на файлы
docker exec -it zumba_php ls -la /var/www/html/admin/
```

### Проблема: Сессии не сохраняются

**Решение:**
```bash
# Проверить директорию сессий
docker exec -it zumba_php ls -la /tmp/sessions/

# Проверить права
docker exec -it zumba_php stat /tmp/sessions/

# Пересоздать директорию
docker exec -it zumba_php rm -rf /tmp/sessions
docker exec -it zumba_php mkdir -p /tmp/sessions
docker exec -it zumba_php chmod 777 /tmp/sessions
```

### Проблема: Логи не записываются

**Решение:**
```bash
# Проверить альтернативный лог
docker exec -it zumba_php ls -la /var/www/html/logs/

# Проверить права
docker exec -it zumba_php stat /var/log/admin.log

# Создать директорию вручную
docker exec -it zumba_php mkdir -p /var/www/html/logs
docker exec -it zumba_php chown www-data:www-data /var/www/html/logs
```

### Проблема: Ошибка подключения к БД

**Решение:**
```bash
# Проверить доступность БД
docker-compose ps

# Проверить логи БД
docker-compose logs db

# Проверить переменные окружения
docker exec -it zumba_php env | grep DATABASE
```
